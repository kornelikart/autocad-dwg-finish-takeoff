# finishcalc — подсчёт отделки по чертежам AutoCAD

Открытый инструмент для архитекторов, проектировщиков и сметчиков. Берёт чертежи AutoCAD (DWG или DXF), находит на планах помещения и заполняет пустые колонки ведомости отделки: площади потолков, стен и полов. По нормам расхода считает количество материалов на всё здание. Результат выгружается в Excel.

Обычно эти площади считают вручную по каждому помещению. finishcalc делает это за минуты и показывает, где чертёж противоречит сам себе: номер вне контура, тип пола не совпадает с ведомостью, у проёма нет марки.

## Что получается на выходе

Файл `finishcalc.xlsx` с листами:

| Лист | Содержимое |
|---|---|
| Ведомость отделки | форма проектировщика с заполненными площадями потолка, стен и пола и разбивкой стен по зонам |
| Экспликация полов | площадь каждого типа пола |
| Материалы | материал, единица, количество, запас, основание (норма или «прямо с чертежа») |
| По помещениям | площадь пола, периметр, высота, площади стен и потолка, заход пола на стену, проёмы |
| Проверки | предупреждения: что не сошлось в чертеже и что посчитано по умолчанию |

В интерфейсе показан план, где помещения раскрашены по статусу: зелёные без замечаний, оранжевые с замечаниями. Ещё там есть чат по результату, где можно спросить, например, «сколько керамогранита на 2-м этаже».

## Установка

Нужен Python 3.10 или новее.

```bash
git clone https://github.com/kornelikart/autocad-dwg-finish-takeoff.git
cd autocad-dwg-finish-takeoff
python -m venv .venv
# Windows: .venv\Scripts\activate    Linux/macOS: source .venv/bin/activate
pip install -e .
```

**ODA File Converter** нужен только для DWG. Бесплатно скачать: [opendesign.com/guestfiles/oda_file_converter](https://www.opendesign.com/guestfiles/oda_file_converter). Программа ищет конвертер в `C:\Program Files\ODA\<версия>\` или по пути из переменной `ODA_FILE_CONVERTER`. Без конвертера (и на Linux/macOS) загружайте DXF: AutoCAD сохраняет его через «Сохранить как».

**ИИ.** Скопируйте `.env.example` в `.env` и впишите ключ [Mistral](https://console.mistral.ai/):

```
MISTRAL_API_KEY=ваш_ключ
```

Запасной вариант без интернета — локальная модель [Ollama](https://ollama.com/): `ollama pull qwen3.5`. Без ключа программа обращается сразу к Ollama, а при ошибке Mistral переключается на неё сама. Ответы ИИ кэшируются в `.cache/llm.json`, поэтому повторный расчёт того же проекта работает и без сети.

## Запуск

```bash
streamlit run app.py
```

Откроется страница с четырьмя шагами:

1. **Загрузка.** Планы этажей и, если таблицы лежат отдельно, файлы с общими данными (ведомость отделки, экспликации, спецификации).
2. **Профиль.** В каких слоях лежат контуры помещений и проёмы, какие блоки служат номерками помещений и метками типа пола. Почти всё находится по правилам, остальное подсказывает ИИ. Любое значение можно поправить в выпадающем списке, а профиль сохранить для следующих запусков. Под формой виден план с найденными помещениями.
3. **Параметры.** Высоты помещений по этажам и справочник норм расхода в редактируемой таблице.
4. **Результат.** Таблицы, предупреждения, план, кнопка «Скачать Excel» и чат по результату.

Для показа удобна демо-папка: задайте `FINISHCALC_DEMO_DIR=<папка с DWG/DXF>`, и на шаге 1 появится кнопка «Открыть демо-проект». Планами считаются файлы со словом «ПЛАН» в имени, остальные файлы считаются общими данными.

## Что должно быть в чертеже

| Данные | Как их ищет программа |
|---|---|
| Контуры помещений | замкнутые полилинии на своём слое; дуги учитываются |
| Номер помещения | блок-номерок с атрибутом; номер относится к наименьшему контуру, в который попала точка вставки |
| Тип пола | блок с атрибутом типа внутри контура |
| Двери и окна | блоки на слое проёмов; марка — ближайший MTEXT на слое марок, размер — по спецификации проёмов |
| Таблицы | объекты `ACAD_TABLE`; вид определяется по заголовку: «Ведомость отделки», «Экспликация помещений N-го этажа», «Экспликация полов», «Спецификация заполнения проёмов». Безымянная таблица с той же шапкой справа считается продолжением |

Номера сопоставляются без учёта пробелов и похожих латинских букв: «A11» и «А11» — одно помещение.

**Два режима.** Если в чертежах есть ведомость отделки, расчёт идёт по решениям проектировщика (режим A). Если ведомости нет, ИИ предлагает типовую отделку по названию помещения, а интерфейс предупреждает, что её нужно проверить (режим B).

## Как считается

- Пол и потолок — площадь контура.
- Стены — периметр × высота за вычетом проёмов. Если стена описана зонами («плитка до 1800 мм, окраска выше»), каждая зона считается отдельно, с вычетом тех частей проёмов, которые в неё попадают. Полоса стены, не описанная в ведомости, идёт отдельной строкой «не указано в ведомости» и попадает в предупреждения.
- «Завести пол на стену на N мм» — полоса добавляется к полу и вычитается из нижней зоны стены.
- Высота из описания потолка («h=3,0 м», при диапазоне берётся максимум) главнее высоты этажа.
- Материалы в кг и л — площадь × расход на м² × число слоёв × (1 + запас). Материалы в м² (керамогранит, ламинат, подвесной потолок) — площадь × (1 + запас). Слои пола с толщиной считаются в м³: площадь × толщина.
- Позиция, которой нет в справочнике, попадает в «Материалы» площадью с пометкой «норма не задана».
- Округление: м² до 0,1, м³ до 0,01.

Нормы в `src/finishcalc/norms.yaml` **предварительные**: проверьте их у сметчика. Правки из интерфейса сохраняются в `.cache/norms.yaml`.

## Где работает ИИ

ИИ переводит свободный текст в ключи справочника и роли слоёв, но **не считает площади и количества**: все числа считает модуль `calc` обычной арифметикой, и их можно проверить.

| Задача | Вход | Выход |
|---|---|---|
| Профиль чертежа | имена слоёв и блоков, образцы текстов | какой слой или блок за что отвечает (только для того, что не нашли правила) |
| Разбор отделки | «Штукатурка, окраска ВД в 2 слоя» | позиции справочника `plaster_gypsum`, `primer`, `paint_wd` |
| Разбор полов | «1. Керамогранит — 20 мм; 2. Стяжка — 50 мм» | слои с толщинами и способом подсчёта |
| Режим B | «Санузел» | типовая отделка потолка, стен и пола |
| Чат | вопрос и итоговые таблицы | ответ, найденный в таблицах, или «в данных этого нет» |

Модель — `ministral-14b-latest` через Mistral API, температура 0, ответ строго по JSON-схеме: ИИ может выбрать только существующий слой, блок или ключ справочника. Если подходящего слоя нет, интерфейс просит выбрать его вручную.

## Ограничения

- Откосы проёмов не считаются, это написано в отчёте.
- Высоты этажей вводятся вручную: разрезы программа не читает.
- Таблицы, нарисованные отрезками и текстом, а не `ACAD_TABLE`, не распознаются.
- Фасады и типовые этажи, не загруженные на шаге 1, в расчёт не входят.
- Это не плагин AutoCAD: чертежи читаются из файлов.

## Проверка на своём проекте

```bash
python scripts/acceptance.py <папка с DWG/DXF> --height подвал=2.7 --height 1=3.3 --height 2=3.3
```

Скрипт считает проект, сохраняет `<папка>/finishcalc.xlsx` и сверяет площади пола с колонкой «Площадь» ведомости отделки. Код возврата 0, если совпало (±0,1 м²) не меньше 90% помещений и у каждого помещения ведомости есть площади или предупреждение. Сохранённый в интерфейсе профиль подключается ключом `--profile .cache/profile.json`.

## Тесты

```bash
pip install -e ".[dev]"
python -m pytest
```

Тесты не ходят в сеть: ИИ подменён, чертежи синтетические и создаются через `ezdxf`. Два теста конвертации DWG пропускаются, если ODA File Converter не установлен.

## Конфиденциальность

Реальные чертежи кладите в `data/`. Эта папка, `.cache/` (кэш ИИ, профиль, нормы), `.env` и все `*.dwg` перечислены в `.gitignore` и в репозиторий не попадают.
