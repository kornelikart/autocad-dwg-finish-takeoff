# finishcalc — подсчёт отделки по чертежам AutoCAD

Дата: 2026-10-25 · Статус: дизайн согласован в чате, спецификация на проверке

## 1. Цель

Открытый инструмент для архитекторов и проектировщиков: по чертежам AutoCAD (DWG/DXF) заполняет площади в ведомости отделки помещений и считает количество отделочных материалов для стен, полов и потолков по всему зданию.

Контекст: хакатон «Вайбкодинг ФКН», тема «Open Source × AI». Код в публичном репозитории под MIT. Критерии жюри: оригинальность 25%, польза 20%, работоспособность 20%, качество 15%, команда 10%, использование ИИ 10%.

Критерий успеха: на защите загружаем чертежи реального проекта и за минуты получаем Excel с заполненной ведомостью отделки и сводкой материалов; площади полов совпадают с площадями проектировщика.

## 2. Что показало исследование реального проекта

Файлы: планы нижних этажей и лист общих данных с узлами и спецификациями. DWG переведены в DXF 2018 через ODA File Converter 27.9. Единицы — миллиметры (`$INSUNITS = 4`).

| Данные | Где лежат | Как читаются |
|---|---|---|
| Контуры помещений | слой `_AREA`; замкнуты не все полилинии | `ezdxf.path.make_path(...).flattening()` → shapely `Polygon` |
| Номер помещения | блок `номерок`, атрибут `ААА` | точка вставки внутри контура |
| Тип пола | блок `тип пола`, атрибут `ТИП`; значения вида 7, 7* | точка вставки внутри контура |
| Экспликация помещений | `ACAD_TABLE` на планах, заголовок «Экспликация помещений N-го этажа» | `read_acad_table_content` + `plain_mtext` |
| Ведомость отделки помещений | `ACAD_TABLE` в ОД, 9 колонок: № · наименование · потолок · площадь · стены · площадь · пол · площадь · примечание | то же |
| Экспликация полов | `ACAD_TABLE` в ОД: № пом. · тип пола · схема · данные элементов · площадь | то же |
| Спецификация проёмов | `ACAD_TABLE` в ОД: марка (ДС-3…) · ГОСТ · размеры В-Ш · количества по этажам | то же |
| Двери и окна | слой `_WinDoo`, динамические блоки `*U…`; марки дверей — MTEXT на `_обозначения дверей`, окон — на `_обозначения проемов` | ближайшая марка → размер из спецификации |

Проверка площадей: почти все контуры содержат ровно один номер; у большинства помещений площадь контура совпадает с экспликацией в пределах ±2%. Для подвала расхождение с экспликацией больше, но площади совпадают с колонкой «площадь пола» ведомости отделки — ведомость считали по этим контурам.

В ведомостях проектировщика колонки «Площадь м²» для потолка и стен пустые. Их заполнение — основная ценность продукта.

## 3. Режимы

- **Режим А (основной).** В проекте есть ведомость отделки и экспликация полов. Инструмент берёт решения проектировщика и считает по ним площади и материалы.
- **Режим Б (запасной).** Ведомости нет. ИИ предлагает отделку по названию помещения из справочника, пользователь правит, дальше расчёт как в режиме А.

## 4. Архитектура

Конвейер: DWG → DXF → извлечение → профиль проекта → сопоставление → разбор описаний (ИИ) → расчёт → проверка в интерфейсе → Excel.

| Модуль | Ответственность | Зависит от |
|---|---|---|
| `convert` | DWG → DXF через ODA File Converter (`ezdxf.addons.odafc`) | ODA File Converter |
| `profile` | Профиль проекта: роли слоёв, блоков и атрибутов. Автоопределение (правила, затем ИИ для спорного), подтверждение пользователем, сохранение в JSON | `extract`, `llm` |
| `extract.rooms` | Помещения: контур, номер, тип пола, площадь, периметр; проблемные случаи → предупреждения | ezdxf, shapely |
| `extract.tables` | Поиск и разбор таблиц по ключевым словам заголовка (ведомость отделки, экспликация полов с продолжениями, экспликация помещений, спецификация проёмов) | ezdxf |
| `extract.openings` | Проёмы: блок → ближайшая марка → размер; помещения, к границе которых примыкает проём | ezdxf, shapely |
| `llm` | Клиент Mistral, ответы по JSON-схеме, кэш на диске, запасной вариант Ollama | requests |
| `finishes` | Разбор описаний отделки и составов полов в структуры | `llm` |
| `calc` | Чистые функции расчёта площадей и материалов, без ввода-вывода | — |
| `export` | Excel | openpyxl |
| `app` | Интерфейс Streamlit | всё выше |

Каждый модуль тестируется отдельно; `calc` и разбор строк таблиц не зависят от ezdxf.

## 5. Модель данных

- `Profile`: `room_contour_layer`, `room_tag_block`, `room_tag_attr`, `floor_tag_block`, `floor_tag_attr`, `openings_layer`, `door_mark_layer`, `window_mark_layer`, `units_mm_per_unit`.
- `Room`: `number` (нормализованный), `name`, `floor` (этаж), `polygon`, `area_m2`, `perimeter_m`, `floor_type`, `finish` (`FinishSpec`), `openings`, `warnings`.
- `FinishSpec`: `ceiling` (материал, `height_m` при «h=…»), `walls` (список `Zone`), `floor` (материал, `upturn_m` при «завести на стену»).
- `Zone`: `from_m`, `to_m` (`None` = до высоты H), `items` (материалы), `source_text`.
- `FloorType`: `code` (7, 7*…), `layers`: `[{material, thickness_mm_min, thickness_mm_max, count_as: volume|area|piece}]`.
- `Opening`: `kind` (door|window), `mark`, `width_m`, `height_m`, `rooms`, `size_source` (spec|default).
- `MaterialLine`: `material`, `unit`, `quantity`, `reserve_pct`, `basis` (чертёж|норма|по умолчанию), `rooms`.
- `Warning`: `code`, `room`, `message`.

## 6. Извлечение

1. **Нормализация номера помещения.** Латинские буквы, похожие на кириллические (A, B, C, E, H, K, M, O, P, T, X), заменяются на кириллические; пробелы убираются. В экспликации встречаются и «A11», и «А15».
2. **Сопоставление.** Номер внутри контура → строка ведомости отделки и экспликации помещений по нормализованному номеру. Тип пола — по треугольнику внутри контура.
3. **Этаж помещения** — из заголовка таблицы экспликации, в которой оно найдено («1-го этажа», «подвального этажа»). Не нашлось → «не определён» и высота по умолчанию.
4. **Таблицы** распознаются по ключевым словам первых строк. Таблица без заголовка, стоящая рядом и с той же шапкой, считается продолжением.
5. **Проёмы.** Для каждого блока на слое проёмов ищется ближайшая марка в радиусе 1,5 м. Размер — из спецификации по марке: «ДС 1Рп 21,5 … 10» → высота 2150 мм, ширина 1000 мм (разбор правилами, ИИ — если правила не справились). Без марки — по умолчанию: дверь 0,9 × 2,1 м, окно 1,5 × 1,5 м, с предупреждением. Проём относится к помещениям, граница которых проходит на расстоянии не больше 300 мм от центра блока.
6. **Предупреждения:** контур без номера; два номера в контуре; номер без контура; помещение без строки ведомости; строка ведомости без контура; тип пола противоречит ведомости; проём без марки; неописанная полоса стены.

## 7. Расчёт

Для каждого помещения, H — высота отделки стен:

- H — высота помещения от пола до потолка: значение этажа из параметров; если в описании потолка есть «h=X м», то X.
- Проём занимает по высоте отрезок [низ; низ + высота]: у двери низ = 0, у окна — высота подоконника (по умолчанию 0,9 м).
- Пол: `S_пол = площадь контура`. Если «завести на стену на N мм»: `S_заход = (P − Σ ширин дверей) × N`, добавляется к материалу пола и вычитается из нижней зоны стены.
- Потолок: `S_пот = S_пол`.
- Стены: `S_ст = P × H − Σ ширина × |[низ; верх] ∩ [0; H]|` по проёмам этого помещения. Откосы в MVP не считаются, это указано в отчёте.
- Зона стены [a; b]: `S_зоны = P × (b − a) − Σ ширина × |[низ; верх] ∩ [a; b]|`.
- Неописанная полоса (например, 1800–2100 мм) считается отдельной строкой «не указано в ведомости» и попадает в предупреждения.
- Материалы: каждая позиция зоны, пола или потолка × норма из справочника × (1 + запас). Слои полов: `count_as = volume` → м³ = S_пол × толщина (при диапазоне толщин — среднее и предупреждение); `area` → м² × (1 + запас).
- Округление: площади до 0,1 м², объёмы до 0,01 м³.

Справочник норм — YAML, редактируется в интерфейсе. Значения по умолчанию предварительные и должны быть проверены специалистом: штукатурка гипсовая 8,5 кг/м² на 10 мм, слой 10 мм; шпаклёвка 1,0 кг/м²; грунтовка 0,15 л/м²; краска ВД 0,15 л/м² × 2 слоя; керамогранит +10%; плиточный клей 5 кг/м²; подвесной потолок +5%; ламинат +5%; рулонная гидроизоляция внахлёст +15%. Позиция без нормы выводится в м² с пометкой «норма не задана».

## 8. ИИ

Модель — `ministral-14b-latest` через Mistral API. Ответ — по JSON-схеме, температура 0. Замер: определение ролей 9 слоёв за 6,3 с без ошибок; локальная qwen3.5 9B — около 65 с и две ошибки.

Задачи:
1. Профиль проекта: слои (имя, типы объектов, примеры текста) и блоки (имя, атрибуты, примеры значений) → роли. Сначала правила, ИИ — для неоднозначных случаев.
2. Разбор описаний отделки (уникальные строки ведомости) → `FinishSpec`.
3. Разбор составов полов (строки экспликации полов) → `FloorType.layers`.
4. Режим Б: название помещения → отделка из справочника.
5. Чат по результату (бонус): вопрос + итоговые таблицы → ответ.

Кэш: ключ — хэш (задача, модель, вход), значение — JSON-ответ, файл `.cache/llm.json`. Запросы задачи 2 идут параллельно в пределах лимита. Без интернета — Ollama (`qwen3.5`) и кэш; кэш демо-проекта готовится заранее и не попадает в репозиторий.

ИИ не считает площади и количества: все числа считает `calc`.

## 9. Интерфейс (Streamlit)

1. Загрузка: файлы планов и общих данных (DWG или DXF), автоконвертация.
2. Профиль: найденные роли с выпадающими списками; картинка плана с подсвеченными контурами, номерами и треугольниками.
3. Параметры: высоты по этажам; справочник норм в редактируемой таблице.
4. Результат: таблица по помещениям; сводка материалов; список предупреждений; план с раскраской помещений по статусу; кнопка «Скачать Excel».

## 10. Выгрузка Excel

Листы: «Ведомость отделки» (форма проектировщика с заполненными площадями потолка, стен и пола, плюс колонка зон); «Экспликация полов» (площадь по каждому типу); «Материалы» (материал, единица, количество, запас, основание); «По помещениям»; «Проверки».

## 11. Тестирование и приёмка

- pytest: `calc` на синтетических помещениях (прямоугольник, Г-образное, с проёмами, с зонами и заходом на стену); `extract.rooms` и `extract.openings` на синтетическом DXF, созданном ezdxf; разбор таблиц — на массивах строк; нормализация номеров; разбор марок проёмов.
- `llm` тестируется с подменой клиента; один ручной прогон на реальном API.
- Приёмка на реальном проекте: площади полов совпадают с колонкой «площадь пола» ведомости проектировщика (±0,1 м²) минимум у 90% сопоставленных помещений; для каждого помещения из ведомости на загруженных планах заполнены площади потолка и стен либо есть предупреждение с причиной.

## 12. Конфиденциальность и ключи

- Чертежи реального проекта используются только локально: каталоги с реальными DWG/DXF и кэш ИИ — в `.gitignore`. В репозитории — только синтетические тестовые файлы.
- Ключ Mistral хранится в `.env` (в `.gitignore`), в коде — только чтение `MISTRAL_API_KEY` из окружения.

## 13. Вне рамок MVP

Типовые этажи и фасады; чтение высот с разрезов; откосы; плагин AutoCAD; OCR таблиц, нарисованных отрезками; точные нормы расхода по паспортам материалов.

## 14. Риски и запасные варианты

| Риск | Запасной вариант |
|---|---|
| Проёмы сопоставляются плохо | двери и окна по умолчанию с предупреждением; функциональность расчёта не страдает |
| Нет интернета на защите | Ollama + заранее подготовленный кэш |
| ИИ неверно разобрал описание | структура показывается в интерфейсе и правится вручную |
| Не успеваем | порядок отказа: чат → режим Б → проёмы по спецификации → картинка плана. Не трогаем: извлечение → ведомость → площади → Excel |

## 15. Открытые вопросы

- Высоты этажей подвала, 1-го и 2-го этажей: ввести вручную по разрезам (значения по умолчанию в интерфейсе — 3,0 м).
- Значения норм расхода в справочнике — проверить у практикующего проектировщика или сметчика.
